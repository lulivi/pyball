# Team Display Names — Design Spec

**Date:** 2026-04-20

## Summary

Replace the hardcoded team display names "Claro" and "Oscuro" (currently in the static HTML
header and scattered through the codebase) with configurable values loaded from `config.toml`.
The internal domain identifiers ("A" / "B") remain unchanged throughout the system — no data
migration, no API contract changes, no frontend logic changes.

## Motivation

The static HTML (`static/index.html`) has "Claro" and "Oscuro" hardcoded in the score header.
Telegram message formatters use `team.name` directly (i.e., the raw "A"/"B" identifiers) instead
of human-readable names. Centralising display names in config makes the system consistent and
lets any group rename their teams without touching code.

## What Does NOT Change

- `Team.name` domain field — stays `"A"` / `"B"`
- JSON persistence format — no migration needed
- `balance.py` win-detection logic — still `team.name == "A"/"B"`
- HTTP API contract (`FinalScore.A`, `FinalScore.B`, `GoalEvent.team`)
- Frontend JS team-selection logic (`'A'` / `'B'` identifiers)

## Changes

### 1. Configuration

`example.config.toml` and `config.toml` gain a new optional field under `[pyball]`:

```toml
# Optional: Display names for the two teams (shown in Telegram messages and the match UI)
team_display_names = ["Claro", "Oscuro"]
```

`PyballSettings` dataclass adds:

```python
team_display_names: tuple[str, str] = ("Claro", "Oscuro")
```

`load_settings()` reads `pyball_cfg.get("team_display_names", ["Claro", "Oscuro"])` and supports
the env var `PYBALL_PYBALL_TEAM_DISPLAY_NAMES` (comma-separated, e.g. `"Claro,Oscuro"`).

### 2. Telegram formatters (`pyball/bot/formatters.py`)

`format_main_message` and `format_match_result_message` currently use `team.name` to label teams.
Both functions receive a new `team_display_names: tuple[str, str]` parameter. Teams at index 0
and 1 use `team_display_names[0]` and `team_display_names[1]` respectively.

All call sites in `pyball/bot/handlers/meetup.py` pass
`settings.pyball.team_display_names` (settings are already available in handlers via
`context.bot_data["container"]._settings` or injected directly).

### 3. `start_match.py` URL generation

The URL query string gains two new parameters:

```
?date=...&teamA=Luis,Dani&teamB=Rafa,Pedro&nameA=Claro&nameB=Oscuro
```

`StartMatch` receives `team_display_names: tuple[str, str]` (injected by `Container.start_match()`
from `self._settings.pyball.team_display_names`) and includes `nameA` / `nameB` in the
`urllib.parse.urlencode` call.

### 4. `static/index.html` — remove hardcoded names

The two `<div class="team-name">` elements currently contain the literals "Claro" and "Oscuro".
They are replaced with placeholder IDs:

```html
<div class="team-name" id="name-a">—</div>
...
<div class="team-name" id="name-b">—</div>
```

`initApp()` reads `params.get('nameA') || 'A'` and `params.get('nameB') || 'B'` and sets
`document.getElementById('name-a').innerText` and `document.getElementById('name-b').innerText`.
The fallback `'A'`/`'B'` ensures the page still works if the URL was generated by an older version
of the app.

## Data Flow

```
config.toml
  └─ PyballSettings.team_display_names
       ├─ Container.start_match()  →  StartMatch  →  URL ?nameA=Claro&nameB=Oscuro
       │                                                  └─ index.html reads nameA/nameB
       └─ Handlers (meetup.py)     →  formatters  →  Telegram messages show "Claro"/"Oscuro"
```

## Testing

- Unit tests for `format_main_message` and `format_match_result_message` pass
  `team_display_names=("Claro", "Oscuro")` and assert rendered output uses those names.
- Unit test for `StartMatch` asserts `nameA` and `nameB` appear in the generated URL.
- `load_settings()` unit test (or inline check) covers the new `team_display_names` field with
  default and custom values.
- No new integration tests are required — the change is purely cosmetic/display.
